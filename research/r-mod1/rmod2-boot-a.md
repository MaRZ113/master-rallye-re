# R-MOD2 BOOT-A — DirectInput proxy forwarding

## Scope and status

This is the first launcher-free checkpoint. It builds an x86 `dinput8.dll`
which forwards DirectInput8 exports to the Windows system `dinput8.dll`. It
does not load the R-MOD runtime core and installs no game-memory patches.
The launcher remains the known diagnostic fallback. BOOT-A is a test artifact,
not a gameplay release and not yet supported for normal use.

## Exact retail startup path

The supported retail image is PE32/I386, SHA256
`bf8aef32407eb6552c05045b8abef149f32983cedd9503b865069b444c5f96b4`.
It statically imports `DINPUT8.dll!DirectInput8Create` through the IAT at
`0x0068F020`; the native thunk at `0x005FBF20` jumps through that IAT.

The exact-build Ghidra export shows:

```text
entry 0x005C4602
  -> FUN_006766A0
  -> FUN_005AFB20
  -> FUN_00652F50
  -> FUN_00570E00
  -> DirectInput8Create at 0x00570E21
  -> return to FUN_005AFB20
  -> FUN_005AFE30 main frontend loop
```

`FUN_00570E00` obtains the DirectInput device before returning success to its
startup owner. The owner enters the long-running frontend loop only after the
graphics/input setup succeeds. The mode-specific roster-generation and
Challenge preview hooks in F3 are used by subsequent menu actions. This makes
the first forwarded DirectInput call a plausible initialization boundary for
BOOT-B. Static call-chain evidence does not prove the actual runtime ordering
on every Windows configuration; that remains a Windows game test gate.

## Proxy implementation

`DllMain` is inert (the proxy uses the static CRT, so it does not disable
thread attach notifications). It performs no module load, file access,
waiting, patching or thread creation under loader lock. Each exported wrapper resolves the system
DLL through the process-architecture-specific `GetSystemDirectoryW` path and
`LoadLibraryExW(..., LOAD_LIBRARY_SEARCH_SYSTEM32)`. The resolved path is
checked against the loaded module path and against the local proxy handle to
refuse recursive forwarding. `INIT_ONCE` serializes resolution.

The x86 proxy preserves the audited host system export contract: six exported
names and ordinals 1 through 6. `DirectInput8Create` retains the WINAPI/stdcall
signature and forwards arguments and result unchanged. The other five exports
are forwarded by typed wrappers. There is no static import of `dinput8.dll` in
the proxy.

Host inspection of `C:\Windows\SysWOW64\dinput8.dll` with MSVC `dumpbin`
reported the same six name/ordinal pairs. `tools/audit_dinput8_exports.py`
independently parses the PE32 export directory and is also run against the
built proxy. The Windows x86 harness loads the proxy by full path, checks every
name and ordinal, and compares DirectInput error behavior and joystick format
identity with the system DLL.

## BOOT-B design boundary

The gameplay installer must consume the same F3 `native_plan.hpp` generated by
`tools/r_mod1_native_plan.py` and must use the F3 runtime callbacks. The
in-process plan must omit `oep-bootstrap`: the process already passed the OEP
when DirectInput is first called, so that entry trampoline must never be
installed or replayed. All selected preimages, module mapping, code/data
allocations, configuration, and page state must be validated before native
writes. In-process installation additionally needs a quiescent-thread and
verified rollback strategy; it must not assume that the suspended-launcher
transaction can be copied unchanged into a live process.

The original `d3d8.dll` stays untouched. The DLL-vs-DLL graphics combination,
actual game input, renderer behavior, Results, shutdown and a second launch are
human gates. A foreign `dinput8.dll` must never be overwritten; an installation
must refuse to replace an existing proxy without an explicit compatible
chainloader design.

## Candidate and handoff

The BOOT-A ZIP contains only `dinput8.dll` and a short test README. Test it in a
disposable copy of the exact retail installation. First test without a graphics
proxy, then with the existing graphical `d3d8.dll` unchanged. Launch the
original `MRallye.exe` normally; no console or launcher is involved. Remove
only the BOOT-A `dinput8.dll` to uninstall. The Randomizer is not active in
this checkpoint.

Do not label BOOT-A or the eventual DLL path supported until the owner confirms
actual Windows game tests. Seven-AI T1/T2 same-class cases remain a known
unqualified stability concern; any initial integrated package exposing them
must remain BETA or explicitly limit its advertised range.
