# R-MOD1 standalone Randomizer and AI Extender architecture

## Product boundary

R-MOD1 is an independent stock-vehicle gameplay mod. It does not load,
discover, or require the Vehicle SDK, addon manifests, addon assets, or the
Vehicle Runtime. Observatory is optional read-only diagnostics. The original
retail executable remains byte-unchanged on disk; the supported activation
path is the external suspended-process launcher. The graphical `d3d8.dll` is
never replaced or modified. DLL proxy and renderer compatibility remain
unqualified.

Supported executable identity is PE32/I386, size 3,121,214 bytes,
SHA256 `bf8aef32407eb6552c05045b8abef149f32983cedd9503b865069b444c5f96b4`.
The launcher checks the on-disk file and the suspended mapped image, verifies
all selected preimages and allocations, writes/readbacks the complete
operation set, and resumes only after complete installation. Failure before
resume terminates the child. Unknown builds fail closed.

## Independent feature ownership

The Randomizer selects AI class/vehicle policy at native roster generation.
The Opponent Extender changes the Quick Race one-through-seven AI selector and
its startup-bounded count. Either feature works without the other. In V2,
Stock is a per-mode policy off switch; selector hooks remain present so a live
policy edit can take effect at the next fresh roster boundary. Returning
Stock from the callback preserves native selection.

No patch installs a fixed CarN lineup, changes player identity, chooses
DriverID, or creates participant objects. The native chooser retains physical
CarID/DriverID selection, roster storage, and participant lifecycle. Repeated
CarIDs remain distinct native slots; a seven-AI duplicate race still requires
human qualification.

## Staged native plans

All candidates are generated by `tools/r_mod1_native_plan.py` from the exact
retail preimages and their matching x86 runtime DLL. Code and data are placed
in fixed remote allocations after the launcher verifies free ranges. Image
operations include original bytes, feature owner and purpose; overlapping
operations/code/data are rejected.

| Checkpoint | Image operation count | Enabled owners |
|---|---:|---|
| v13 reference | 7 | bootstrap, Quick Race selector, ONE-SEVEN count UI, Quick Race Start |
| F1 | 7 | v13 owners plus V2 Quick Race live policy snapshots |
| F2 | 13 | F1 plus new Master Rallye and shared Rallye Cup/Invitation roster generation selectors |
| F3 | 17 | F2 plus Challenge Preview reset/prepare and race-consume hooks |

F1 preserves the prior seven-operation Quick Race operation bytes. F2 adds
only class-policy seams inside the audited Master and Cup/Invitation native
builders. It does not hook stage publication, save/load, Resume, or roster
reuse. Invitation's native type selects the ordinary T3 policy context; its
bonus/progression T3 entries stay excluded.

F3 prepares one absolute opponent CarID at Challenge preview generation. The
native display code uses that identity for its name and model. Start consumes
the cached selection instead of drawing again. Stock retains the authored
matchup; Back/reentry clears the cache. The Challenge title, human car,
DriverID, objectives, and event rules remain native-owned.

The fixed Quick Race count and Start hooks retain the v13 ABI and false
SplitScreen-veto correction. The removed v10 Broker getter observer remains
absent. No hook wraps the native `RET 4` Broker getter at `0x0040869B`.

claimed as R-MOD runtime qualification.

## Configuration snapshots

ConfigVersion=2 separates five policies: QuickRace, RallyeCup, MasterRallye,
Invitation and Challenge. The native callback reads one strict, stable INI
snapshot at the first selector call of a new roster; the entire selection
generation shares its policy, generation ID and config hash. Invalid or
changing files retain the last valid snapshot. Startup-scoped
`MaxOpponents`, addon policy and Logging are not hot-reloaded.

Challenge is separately cached because preview generation and race start are
different callbacks. The key is the active event and authored human/opponent
pair. The cached display identity cannot be replaced by a policy edit while
visible.

## Evidence levels

- R-MOD v11: owner-confirmed combined one-human/four-AI Quick Race participant
  presence. It remains the known-good runtime reference.
- R-MOD v13: corrected Quick Race package was statically verified; do not
  promote the supplied false-veto report to a new successful race.
- R-MOD F1/F2/F3 implementation, native plans, package builds, and synthetic
  tests are static evidence until the owner tests each candidate.
- Historical R-AI1.2/R-AI1.2a mode and Challenge-preview passes came from
  separate research candidates. They are regression oracles, not R-MOD
  runtime proof.
- The R-GRID8 corpus audit found authored slots, not universal spawn clearance.
  Course safety and extended-count gameplay remain separate human gates.
