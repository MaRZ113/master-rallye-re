# Mercedes name and localization channels

The source record's literal internal/resource name is `Mercedes` in both PC demos. The demo executable strings also contain the exact localized vehicle label `MERCEDES ML-320` (demo-8.4.1 file offset `0x1E9CE8`; demo-9.3.1 file offset `0x26B8EC`). Demo-8.4.1 also contains the model-node identifiers `Mercedes_ML320` and `frontend\\vehicleselect\\mercedesml320` in an old scene. Those are scene/resource names, not the visible label. The compact visible string is the evidence-backed historic name.

The retail executable contains no ASCII `Mercedes` string, although the retail physics XML has a `Vehicles/Mercedes` family. Retail Vehicle Select uses separate group `0x33` manufacturer and `0x34` model lookups; Quick Race uses a separate group `0x35`. The F.1 cleanup currently aliases ID26 to donor ID0 in all three display contexts (and its Quick Race wrapper fixes the old unknown-selector failure). Do not repurpose the actual runtime ID or globally rename ID0.

The demo executables also contain standalone `MERCEDES` and `ML-320` literals near the combined display label. This source audit did not prove each string's selector/group membership or a retail-compatible selector index. Thus no existing retail Mercedes selector is available. A future ID26-only profile should preserve ID26 for preview/resource/physics and explicitly supply the proven visible text `MERCEDES ML-320` through a bounded display override for the required channels. Keep manufacturer, model, Quick Race name, and internal resource name as distinct values; do not silently equate them.
