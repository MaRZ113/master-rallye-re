# Mercedes name and localization channels

The source record's literal internal/resource name is `Mercedes` in both PC demos. The demo executable strings also contain the exact localized vehicle label `MERCEDES ML-320` (demo-8.4.1 file offset `0x1E9CE8`; demo-9.3.1 file offset `0x26B8EC`). Demo-8.4.1 also contains the model-node identifiers `Mercedes_ML320` and `frontend\\vehicleselect\\mercedesml320` in an old scene. Those are scene/resource names, not the visible label. The compact visible string is the evidence-backed historic name.

The retail executable contains no ASCII `Mercedes` string, although the retail physics XML has a `Vehicles/Mercedes` family. Retail Vehicle Select uses separate group `0x33` manufacturer and `0x34` model lookups; Quick Race uses a separate group `0x35`. The earlier F.1 cleanup profile aliased ID26 to donor ID0 in display contexts; the final profile replaces that with direct ID26-only strings and keeps the physical ID unchanged.

The demo executables also contain standalone `MERCEDES` and `ML-320` literals near the combined display label. No existing retail Mercedes selector is available. The final profile supplies `MERCEDES` and `ML-320` to the two Vehicle Select groups and `MERCEDES ML-320` to the three verified Quick Race group-0x35 sites. It preserves ID26 for preview/resource/physics. Keep manufacturer, model, Quick Race name, and internal resource name distinct. Raw assembly and wrapper flow are in [R5V-F.2e display evidence](../r5v_f_2e/display-override.md); P0 must still confirm actual rendering and absence of `GALOCAL UNKNOWN`.
