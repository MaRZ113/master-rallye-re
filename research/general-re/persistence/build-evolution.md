# Narrow pristine cross-build check

All four inputs were independently hashed this phase. Historical patched copies
were not used as authoritative inputs. The broad R-EXE1 correspondence catalog
provided candidate entry points; new selective imports and assembly checks are
the authority for this comparison. No whole-program remapping was attempted.

The mode filter's cases are stable: skip C, Game-bit+filename compare, Options
bit4, PlayerState bit2, alternate Game-bit excluding tag B. Type B checks and
Value serializers support the same logical XmlFilename concept. Driver ToXml
provides an independent semantic object anchor rather than an address-shift match.

All three demo filters step by **0x94**, while retail steps by **0x1C**. In the
8.4.1 Value serializer Bool is read directly from entry +4; retail dereferences
the payload pointer there. This is evidence for a representation change, not just
code relocation. Full demo entry layouts are not mechanically backfilled from
the retail structure. This resolves the earlier R-EXE1 “provisional stride clue”
for these Broker serializer objects; it does not rename every app-setting
container in the old report.

## Limits of the comparison

The 8.4.1 filter was first exported at interior address 004E2650; that invalid
prototype was rejected and the actual 004E2630 entry was re-exported separately.
Demo imports use analyze=False and exact selected disassembly; unusual autogenerated
calling conventions are not trusted. Mode/offset/branch facts were checked in
assembly. Sentinel **open-time registration** survives in the mapped openers;
the full native file writer/backup sequence was traced only in retail. No claim
is made that every demo has retail's complete persistence lifecycle or backup.

No monotonic evolution is assumed. The observed major storage change is bounded
between 9.10.0 and retail; its motivation, memory/performance impact and all
other container changes remain UNKNOWN.
