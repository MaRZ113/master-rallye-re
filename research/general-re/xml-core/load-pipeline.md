# DataGame XML → Broker

## Read and parse

Retail `00522810` constructs `DataGame/<logical-name>.xml`, normalizes slashes,
registers the logical SaveFile, and creates a 0x28 async job (vtable `00691B28`).
Job +0x20 holds logical file ID; +0x24 holds replacement/reset choice. Request
`005FC950` queues it and can immediately pump the queue when its final argument
is nonzero. “Async” in the class name does not guarantee delayed completion.

Read-success callback `0052D830` parses bytes via `005FDD40 → 005FD0F0 → 005FDE30`.
XML nodes are 0x28: +04 first child, +08 next sibling, +18/+1C/+20 ordered
attribute vector, +24 tag ID. It calls `0052EEB0(root, sourceID, resetFlag)`.
Root Game dispatch recognizes Broker and ParticleRecords; this report follows
the Broker child, not every engine subtree.

## Typed conversion

`005FE060` constructs a temporary manager and iterates Value children.
`005FE120` uses the parser family `004DF130..004DFD60`, then corresponding
typed setters. Accepted types are listed in [Broker types](../broker-core/types.md).
Parsing checks node/attribute IDs and ordered attribute layout. Scalar/name
records typically require 3 or 5 attributes: Name, Type, Value, optionally
SaveOptions and SavePlayerState. XmlData uses its class attribute and children.
Do not interpret ElementTree's ability to parse reordered attributes as proof
the game accepts them.

After each successful Value:

1. Game flag comes from the load-mode argument.
2. Options/PlayerState flags come from optional XML annotations when that mode
   is active; when inactive the loader clears them.
3. Scope is explicitly 0 GLOBAL.
4. SaveFile is the source job's logical filename ID.

The full Name is interned and selects an indexed entry. This is not insertion
into a path-segment tree. Unknown type/bad typed syntax can fail conversion;
there is no generic opaque fallback in the recovered dispatch.

## Publish and follow-up

`0052EEB0` merges via `004D7690`, or resets engine/Broker state with `00522910`
and replaces via `004D78C0` when reset was requested. XmlData payloads are
cloned by the copy operation rather than shallow shared ownership.

Successful `00522B10 → 00522BD0` gathers XmlFilename dependencies belonging
to that source SaveFile and queues them. Failure changes the loader state to
Default and does not follow dependent files. Missing-file handling and effective
ordering are mapped in [load-order.md](../persistence/load-order.md).

Evidence: job vtable words, read/parse callbacks, typed parser+setter assembly,
retail ordered attributes and dependency names. Decompiler's autogenerated
argument declarations are not treated as recovered C++ prototypes.
