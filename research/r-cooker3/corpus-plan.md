# R-COOKER3 source corpus qualification

## Current status (R-COOKER3.1)

The planning table below is historical; Forester is no longer a pending
native-cook candidate. Its supplied outputs are validated and runtime-use was
reported under a temporary Mercedes namespace. The current family-scoped
cache-only package has static PASS, while Forester-named runtime portability
remains pending. Trooper is the next source family prepared for a separate
native cook: `inputs/9.3.1_Trooper` has all three supported GXM/GXI roles,
54 authoring references, 24 unique referenced GXI files, and a ready strategy
plan. See [Trooper preflight](third-family-preflight.md).

Mercedes proves that the strategy split and job orchestration work for one
source family. It does not establish arbitrary GXM support.

| Candidate | Source | Static source result | Cook/runtime result |
|---|---|---|---|
| Mercedes | Demo 8.4.1 `DataGx/Vehicles/Copy of Mercedes` | 3/3 GXM supported prefixes; 25 referenced DXT closure; 25 GXI mirrored | Native Cook A/B identical; T1/T2/T3 closed and runtime-confirmed for the exact harness |
| Forester | Demo 9.3.1 `DataGx/Vehicles/Forester` | 3/3 GXM supported prefixes; 46 authoring references; 23 unique referenced GXI; 23 DXT dependencies | Native cook and model/race/collision/damage use reported at runtime under temporary `Mercedes` namespace; authentic Forester physics not proven |

Forester's frontend GXM is named `comlplete.gxm` in the corpus. Inventory
normalizes its role to `complete` when it stages a copy as `complete.gxm`;
the source file itself is not renamed or modified. Its exact SHA256 is
`3fa2cff8c100b66236b1f076c164a402ac199fe3502838e0bc18be8a381b790f`.
