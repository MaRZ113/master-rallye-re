# Marker-1339 reconstruction

Wire layout is little-endian u32 marker 1339, vec3 f32 center, f32 scalar, vec3 f32 minimum, vec3 f32 maximum: exactly 44 bytes at the end of all 78 vehicle DX resources. The typed DxSpatialBounds1339 model retains the raw block and absolute offset.

Corpus formula probes compared render only, render plus detailed tag101 Representation B, render plus all tag101 geometry, and AABB half-diagonal. The detailed-B set explains the scalar within 1e-5 on 77/78. The all-collision set includes AABB-helper corners and overstates many radii; render-only misses collision extrema. All 25 wheel resources match render-only because they have no tag101. SeatBuggy/complete.dx requires detailed B. Min/max and center agree within 1e-6 and 1e-5 respectively for all 78. See bounds-corpus.json.

WildCat/car.dx: stored radius 2.2644841671, farthest detailed-B distance from stored center about 2.2646759421, gap about 0.000191775. The two farthest B vertices both exceed the stored scalar by roughly this amount; render-only reaches only about 2.1163093. Float32-only arithmetic, double arithmetic then float32 storage, center order, all collision geometry, and AABB half-diagonal do not explain the gap. It likely reflects a stale or independently computed source scalar, but there is no proof of that cause. Targeted executable follow-up used MRallye.exe SHA-256 BF8AEF32407EB6552C05045B8ABEF149F32983CEDD9503B865069B444C5F96B4. The available Ghidra text exports contain no 1339 hit. A read-only search of MRallye.exe found four little-endian 1339 byte sequences in .text; three are embedded branch/call displacements, while file offset 0x153C07 (VA 0x553C07) is an x86 push immediate 0x53B before an indirect call. This is a plausible marker-write site, not a traced radius calculation. No installed Ghidra headless tool or local disassembler was available to follow its scalar computation, so no exact original compiler arithmetic is claimed.

Production policy: preserve the raw block at zero edit. On an explicit bounds update, recompute min/max from render + B, center from their midpoint, and radius from maximum Euclidean distance, rounding the float32 result outward to contain all points. Reject non-finite/large points and reparse output. This is a conservative safety policy, not an exact claim about the original exporter. Of 78 originals, a direct recompute reproduces 26 complete footer byte strings; differences are reported, not hidden.
