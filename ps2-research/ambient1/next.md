# Exactly one next research phase

**Recommend PS2-AMBIENT-RUNTIME1: one controlled spline-owner/transform capture.**
Recommendation only; this phase does not start it or implement a PC port.

1. Is the owner understood for future PC reproduction? **Yes**, for finite
   authored routes and defined instance/observer state, with the proved cubic,
   chord/equal-time clock, lifecycle and matrix publisher. IEEE float32 offline
   reproduction is available; PS2 bit equality is not claimed.
2. What is missing? Actual dispatch cadence, first-init +128/heap behavior,
   PS2 FPU/libm differences, inter-tick rendering/PSM child propagation, and
   observed loading/motion of exact selected Eggs.
3. Shared across boats/barges/airships? **Yes at this owner's code boundary**:
   no family-specific path, height or transform branch. This does not equate
   all model-local visual axes or prove common physics.
4. Need a dedicated runtime capture? **Yes**, highest payoff after the static
   chain, especially because clock/initial bank state and bank-only-up behavior
   now make concrete predictions that a static screenshot cannot validate.
5. Later SDK extension? A read semantic projection over existing preserved
   XML/route records, model/placement identity and runtime-controller descriptor;
   keep bounded current authoring intact until separately authorized.
6. Later PC runtime hook? A proven per-object matrix/lifecycle and logical-tick
   integration, with explicit observer selection and render interpolation.
7. Existing baked PC dinghies? Match individual placements/grouped geometry
   and collision before choosing hide/replace/reuse. Mesh-name counts cannot
   identify the object to remove.
8. Other subsystem leads? Existing bird, rigid-body and vegetation candidates
   remain independent leads. This owner does not prove their route semantics.
9. Single highest-payoff research phase? **PS2-AMBIENT-RUNTIME1**, because it
   closes a precisely defined causal/timing uncertainty for a working contract;
   it is not selected merely from an AMBIENT numbering sequence.

Capture plan, without ELF patches: use canonical SLES/corpus in PCSX2; pin
course/selected Egg, run state, emulator version/settings and speed limiter;
collect a synchronized short video plus read-only debugger/RAM observations.
At init/tick observe owner pointer/vtable/ID, +128 before and after first init,
+68/+6c/+60/+54/+12c, cached pose and `*(entity+50)+20..5c`. Observe the Broker
Car0 payload XYZ and frame/tick sequence. Set read-only breakpoints or use
existing emulator trace facilities, never patch game instructions.

Minimum controlled contrasts: ITALY3 near/far threshold crossings and pause/
resume; TURKEYW open final-marker hold; one SPAINS2 turning boat to check the
up-only bank output. One synchronized capture session can cover these
contrasts; do not broaden into a 24-object gameplay census. Compare captured
**controller invocations**, not nominal rendered frames, with reconstruction.
Acceptance: actual changing en3d matrix matches the path/lifecycle predictions
within a declared tolerance, cadence and first-init flag are measured, and
video links that matrix to the intended visible object. Then—and only then—
assign CONFIRMED_BY_RUNTIME to the observed cases.
