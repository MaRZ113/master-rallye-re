# Путь к ночи и динамическому времени суток — приоритеты (2026-11-05)

Цель: реальная, но стилизованная ночь (фары, фонари, свет окон, тёмная земля, луна, звёзды,
пост-эффекты), затем динамический таймцикл. Classic/Stock остаётся нетронутым, всё opt-in.

## Что уже есть и на что опираемся

* **Resolver переписывает цвет вершин каждого освещённого прохода на CPU** (prelight × ambient/sun,
  кэш по поколению ресурсов). Значит «затемнить мир» и добавить **статичные** точечные источники
  можно тем же путём — без шейдеров (D3D8, fixed function).
* SunFX (спрайты с depth-маской), LiveTuning, региональные пресеты, свой кастомный набор неба,
  адаптеры PC/PS2-воды и spline-объектов, путь Present для своих слоёв (метка закладки, легенда).
* Ограничения: нет пиксельных шейдеров под рукой (PS 1.4 есть на HAL, но не используется), нет
  своих RT для пост-обработки, тени только штатные; рельеф тесселирован грубо — пятно фар на
  вершинах выйдет «ступенчатым».

## Главный вывод

Ночью **всё, что не освещено, светится**: любой пропущенный проход (частицы, PS2-трава, вода,
спрайты, стекло, glow-on) сразу видно. Поэтому сначала покрытие и lamp-контракт, потом ночь.

## Приоритеты

### P0 — фундамент (до ночи)
1. **Аудит покрытия всех трасс** (фаза 2.7 в roadmap): пакетный FreeCam-захват по закладкам на
   каждой трассе, отчёт Lit/Excluded/Unsupported + миниатюры. Цель — список всех неосвещённых
   проходов, а не только тех, что попались на скриншоте.
2. **Нативный glow-on / lamp-контракт (3.0)**: убрать просвечивание и края, привязать
   фары/стопы/габариты к реальным сигналам игры. Без этого ночные фары невозможны.
3. **«Ночной» тест-пресет** только для диагностики: ambient≈0.1 — сразу показывает, что ещё светится.

### P1 — статичная ночь (первый видимый результат)
* Пресет `Night`: лунный направленный свет (холодный, слабый), низкий ambient, тёмно-синий туман,
  без SunFX → **MoonFX** на том же пути (спрайт луны + мягкий ореол, depth-маска).
* Ночной набор неба (`CustomSet`): звёзды, луна на небе согласована с направлением света.
* Затемнение: PS2-трава, физпропы, вода, spline-объекты, отражение окружения машины (env-захват
  неба тёмный — авто-переливов не будет), частицы пыли (иначе «светящаяся пыль»).
* HUD не трогаем.

### P2 — фары машины (главная фича ночи)
* **Проективная текстура фар**: дополнительный аддитивный проход по ближним мировым drawcall'ам
  с текстурой-«пятном» (cookie) через `TEXCOORDINDEX=CAMERASPACEPOSITION` + матрица проекции фары.
  Это попиксельно на fixed function, без шейдеров, и не трогает CPU-кэш вершин (динамический
  свет через пересчёт вершин каждый кадр был бы дорогим и ступенчатым).
* Ограничение по дальности/конусу, только допущенные (Lit) материалы, затухание тумана.
* Спрайты-«блики» фар, стопов, габаритов с depth-маской; яркость стоп-сигнала от тормоза.

### P3 — статичные источники мира
* **Фонари** (`s_light01` и др.): спрайт-ореол + точечный источник, вклад в цвет вершин в том же
  resolver-проходе (статичный → кэшируется, дёшево).
* **Окна зданий**: эмиссивные маски по материалам (SDK: роль `emissive`/маска из альфы или
  авторская карта), включаются в пресете Night; без маски окно остаётся тёмным.
* Чекпоинты, старт/финиш, баннеры с подсветкой — по ролям.
* Позиции источников — экспорт из Course SDK / Blender, не хардкод в DLL.

### P4 — пост-эффекты (ночью дают больше всего)
* **Bloom только от своих источников**: мы сами рисуем спрайты фар/фонарей/луны → можем рисовать
  их ещё и в свой маленький RT, размыть и сложить. Это обходит блокер «нет opaque-only маски»
  из отчёта 03_BLOOM: блюрим не backbuffer, а только собственный свет.
* Мягкая цветокоррекция ночи (холодные тени / тёплые лампы), виньетка уже есть, зерно — опционально.
* Мокрое отражение света фар на асфальте — позже, как вариант проективного прохода.

### P5 — динамический таймцикл
* Ключевые кадры времени суток (рассвет/день/золотой час/сумерки/ночь) как наборы параметров
  пресетов; интерполяция ambient/sun/fog/exposure; солнце и луна по дуге.
* Небо: кроссфейд двух наборов (два слоя уже есть в нативном цилиндре).
* Включение фонарей/окон по порогу освещённости; фары по времени или игроку.
* Пересчёт цвета вершин при смене времени — инкрементально (раз в N кадров), не каждый кадр.
* Режимы `TimeMode=Preset` / `TimeMode=Dynamic`, скорость времени, старт гонки в заданное время.

### Уточнения владельца (2026-11-05)
* **Чекпоинт-борды, старт и финиш** должны светиться ночью и уже в сумерках (сейчас затемняются
  вместе с миром) → роль `emissive`/«подсветка» в P3, включение по порогу освещённости (P5).
* **Задние фонари**: сами излучают свет как фары (не только спрайт) и оставляют **видимый след на
  земле** (красное пятно позади машины, стоп-сигнал ярче) → в P2 вместе с фарами, тем же
  проективным проходом, конус назад.
* **Частицы пыли** пока не реагируют на наш свет → обязательно к полноценной ночи (P1/P2).
* **Налёт пыли, грязи, воды на кузове** с сопутствующими эффектами (капли, потёки, брызги) —
  исследовать заранее (как устроены материалы кузова/повреждений, есть ли у PS2 версии такие
  слои), реализация на этапе PostFX/материалов машины.

### Параллельно/потом
* Арт-беклог 2.8–3.1 (регионы, контраст, кольца солнца, rim, текстуры) — не блокирует ночь.
* Тени машины (контактная тень) — особенно заметна под фонарём; после P3.
* FPS-бюджет: каждый новый проход — с замером (ps2_perf_timing), фары — только ближние draw'ы.

## Предлагаемый ближайший порядок

1. P0.1 аудит покрытия всех трасс (автоматический, отчёт) →
2. P0.2/0.3 lamp-контракт + ночной диагностический пресет →
3. P1 статичная ночь с луной и ночным небом →
4. P2 фары → 5. P3 фонари и окна → 6. P4 bloom своих источников → 7. P5 таймцикл.
