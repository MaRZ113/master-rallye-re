This is a proposed command/capture plan, **not an executed runtime test**. No DLL, runtime hook or spawn is supplied by this preliminary read-only preparation.

1. Keep exact PC executable `bf8aef32407eb6552c05045b8abef149f32983cedd9503b865069b444c5f96b4` and frozen baseline tree. Use the established verified offline race certificate for Turkey3 and the existing single reusable staged PS2 build. Stock remains the default.

3. Identify native Egg creation/registration and deletion routes separately from body creation. Validate four AI slots, name/Broker publication and native list ownership. A private owner must not replace a stock AI; `0x004F5950` destroys an existing slot owner before installing a replacement.
4. Prove an actual convex instance and its body pointer before attempting contact. First use the original PC hay asset as a native format/lifetime control; do not label that control a PS2 tumbleweed.
5. Once a private original PS2 convex resource can be instantiated through the proved path, use only Turkey3 source identity `list:11:egg:13:ai:0`; preserve authored model/hull/mass5/MOI(2,2,2). Record native post-placement pose rather than assuming the authored Y survives collision adjustment.
6. Capture before/during/after one low-speed car strike: exact human vehicle body, exact prop body, contact shape/normal/point, solver state commitment, linear/angular state, then the same visual world matrix. Label PC-solver differences separately from PS2 RIGID1. A moving renderer-only mesh or screenshot is insufficient contact proof.
7. Test race restart, exit to menu, another course and device reset. Device reset must manage GPU resources independently of native physical-scene lifetime. Prove original manager teardown `0x0043E020` and selective retirement/unregistration before exposing a reusable spawn feature. Do not double-free manager-owned bodies.

The immediate static blockers are private convex-resource attachment, owned Egg creation/retirement and load/physics-thread admission. A broader car solver reverse is unnecessary for the first contact/lifetime control. Yellow checkpoint barrels require their own owner/shape check and are deferred until this one-object path is safe.
