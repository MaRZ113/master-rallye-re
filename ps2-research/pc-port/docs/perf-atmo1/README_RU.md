# PERF-ATMO1 — почему фары и закат (Atmosphere) просаживают FPS

Дата: 2026-11-07. База: master 2748563 (ATMOSPHERE 6.16, DLL 172c48a7).

## 1. Что было в логах (Atmo-copy, MRRRenderer\logs)

* `PerfTiming = 0` в RendererDiag.ini → **времени кадра в логах нет ни в одной сессии**.
  Ниже только то, что считает сама атмосфера, и счётчики проходов.
* Сессия 39484 (07.11, GoldenHour, FranceWFlip / SpainM / Spain1×2), сессии 21244 и 42696
  (06.11, Night, Italy1 / Turkey3 / FranceWFlip / France2), MSAA 4x, 1920x1080.
* Сессионный лог упирается в лимит 16 МБ (39484 обрезан в 12:25, игра шла до 12:33).

| Что | GoldenHour (39484) | Night (21244 / 42696) |
|---|---|---|
| Пересвет мира, CPU (`atmosphere_cpu_window`) | 0.74 мс/кадр (p90 1.08) | 0.82 / 1.00 мс |
| Кузова, CPU (`body_cpu_ticks`) | 1.34 мс/кадр, 123 вызова | 0.96 (p90 1.88, max **6.1**) / 0.94 мс |
| Копирование вершин в приватный буфер | 0.2–0.74 МБ/кадр, ~100 + ~120 Lock/кадр | то же |
| Солнце (маска глубины), CPU | ~0.09 мс/кадр | — (луна/звёзды) |
| **Доп. проходы фар** (`atmosphere_headlight_stats`) | 0 | **40–140 полных перерисовок геометрии трассы/кадр** |

Измеренная CPU-часть атмосферы ≈ 2.2–2.5 мс/кадр, то есть сама по себе она «съедает» ~20 % кадра при 100 fps.
Но самые дорогие вещи этими счётчиками **не измеряются вообще** (см. ниже).

## 2. Причины (по убыванию ожидаемого вклада)

### A. Один общий MANAGED-буфер, Lock без флагов ~220 раз за кадр (и закат, и ночь)
`atmosphereintegration::upload()` для **каждой** пересвеченной отрисовки (≈100 курсовых + ≈120 кузовных)
делает `scratch->Lock(..., 0)` у одного и того же `D3DPOOL_MANAGED` буфера, затем `SetStreamSource`.
Пока GPU ещё читает этот буфер для предыдущей отрисовки, драйвер/рантайм при следующей перезаливке
обязан либо ждать GPU, либо переименовывать буфер (до 2 МБ) — это классический «lock stall»,
который даёт именно рваные просадки, а в наших CPU-таймерах не виден (стоимость всплывает внутри
следующего DrawIndexedPrimitive / Present). Устройство ещё и `MULTITHREADED` (behavior_flags 0x54).
Данные при этом статичны: кэш резолвера (2.4 МБ) хранит уже пересвеченные вершины, а мы каждый кадр
копируем их заново.

### B. Фары = повтор всей освещённой геометрии трассы на каждую машину и каждую фару (ночь)
`headlight_world()` после каждой принятой отрисовки трассы перерисовывает её ещё раз
(аддитивный проход, 3 текстурные стадии, проективная текстура) для каждой из ≤4 машин × (фара + стоп-пятно).
По логам 40–140 таких проходов за кадр, на каждый ≈25 Get + ≈50 Set + ≈30 восстановлений состояний,
плюс GetRenderTarget/GetBackBuffer на каждого кандидата → ~10 000 D3D-вызовов за кадр поверх игры,
и ещё столько же растеризации ближней трассы с MSAA 4x. Именно это объясняет, почему «простые» фары так дорогие.

### C. Кузова/фонари: 1–1.9 мс, пики 6 мс (ночь)
Подбор lamp-rig на каждом рисовании линзы (6.15.1), маски линз, glint-кластеры, `geometry()`-зеркала,
LockRect текстур линз (кэшируется, но первые кадры каждой гонки — пики).

### D. Солнце/закат (GPU)
Маска видимости — отдельный полноэкранный MSAA render target: смена RT посреди кадра, Clear 1920×1080,
CopyRects всего экрана; затем 5 смещений × (glow, bloom, лучи, ghosts) больших аддитивных квадов
(лучи 22°, bloom 28° ≈ 700–900 px). CPU мало (0.09 мс), GPU-часть не измерялась.
Каждая правка Atmosphere.ini при LiveTuning=1 сбрасывает кэш резолвера → разовый пик пересвета.

## 3. Диагностическая сборка PERF-ATMO1

Изменения (только диагностика + опция, по умолчанию поведение прежнее):

* `PerfTiming = 1` теперь пишет категории `atmo_world`, `atmo_upload`, `atmo_body`, `atmo_headlight`,
  `atmo_sun_world`, `atmo_sun_ui` (вложенные: upload входит в world/body) и поле `"atmo"` в `ps2_perf_timing`.
* **F6** (`PerfAtmosphereKey = 117` в RendererDiag.ini; в 4544f7f6 была F8 и конфликтовала со свободной камерой),
  только при PerfTiming = 1, по кругу: `none → headlights → lamp_glints → sun_fx → ring_upload →
  world_native → bodies → all`. Каждое нажатие начинает новое окно замера и пишет `ps2_perf_atmo_bypass`.
  * headlights — без проходов фар (и без фар на траве/реквизите);
  * lamp_glints — без звёздочек фонарей;
  * sun_fx — без солнца/луны, звёзд и виньетки;
  * **ring_upload** — тот же вид, но загрузка вершин через DYNAMIC-кольцо (NOOVERWRITE/DISCARD) вместо
    MANAGED Lock(0) — это кандидат на исправление причины A;
  * world_native — трасса рисуется нативно (без пересвета мира; фары тогда тоже не рисуются);
  * bodies — машины в PC-виде (без пересвета кузовов и ночных фонарей);
  * all — headlights + glints + sun + world_native.
* `UploadRing = 1` в Atmosphere.ini включает кольцо постоянно (для обычной игры после проверки).
* Кузова разбиты на стадии `atmo_body_gate` (проверки + поиск владельца), `atmo_body_owner` (материал/права),
  `atmo_body_geometry` (копия вершин + дескрипторы), `atmo_body_shade` (пересвет).
* `atmosphere_cpu_window` дополнительно пишет `ring_uploads` / `ring_discards`.

## 4. Инструкция замера для владельца

1. Поставить d3d8.dll из `dist/perf-atmo1` в `D:\Game\Master Rallye Atmo-copy` (старую сохранить как
   `d3d8.dll.bak-6.16-172c48a7`).
2. В `RendererDiag.ini`: `PerfTiming = 1`, `PerfWindow = 300`. В `Atmosphere.ini`: `LiveTuning=0`
   (чтобы перечитывание INI не сбрасывало кэш посреди замера), `UploadRing` не трогать (0).
   `CoverageLedger=0` (лишняя работа и рост лога).
3. **Замер 1 — ночь** (`profiles\Atmosphere-Night.ini` → Atmosphere.ini), Quick Race, одна трасса
   с лесом/деревней (например France2 или FranceWFlip), с соперниками.
   Остановиться в одном месте **с видом вдоль дороги** и стоять (не пауза и не FreeCam — они меняют
   рендер), лучше рядом с соперником, чтобы его фары тоже светили на трассу.
   На каждом шаге F8 ждать ~10 секунд (2 окна по 300 кадров), затем следующее нажатие.
   Пройти все 7 шагов, потом ещё раз проехать 1–2 минуты в шаге `none` и 1–2 минуты в `ring_upload`.
4. **Замер 2 — закат** (`profiles\Atmosphere-GoldenHour.ini`), та же трасса, солнце в кадре
   (смотреть на солнце): те же 7 шагов F8 по ~10 секунд.
5. Сообщить: модель видеокарты и процессора, держал ли вертикальную синхронизацию / лимит FPS,
   где стоял (трасса и примерно место). Логи берутся автоматически из `MRRRenderer\logs` (session-*.jsonl).
6. Если в `none` и `ring_upload` разница заметна глазами — сказать, были ли артефакты
   (мигание, пропадающая/дёргающаяся трасса, мусорные треугольники) в `ring_upload`.

По этим окнам будет видно: frame_time (avg/p95/p99/max) на каждом шаге → сколько мс стоит каждая часть,
и снимает ли кольцо просадки (причина A). Дальше — план оптимизации по результатам:
кольцо/статические буферы для кэша резолвера; фары одним проходом через карту света сверху
(все машины в одной текстуре вместо N×2 проходов) и пакетная установка состояний;
солнце — маска в малом RT вместо полноэкранного MSAA.

## 5. Второй замер (07.11, DLL 99d3ba54, Spain1, 3 соперника, в движении)

| Шаг | Закат: кадр, мс | Ночь: кадр, мс |
|---|---|---|
| none | 13.7–22.8 (рядом с машинами 17–23) | **32.1 (31 fps)** |
| headlights | 16.2 | 20.4 → фары ≈ **12 мс** |
| sun_fx | 15.1–16.0 | — |
| ring_upload | 14.5 | 29.9 |
| world_native | 14.2 | 16.8–17.6 |
| bodies | 12.3–13.3 → кузова ≈ 2–5 мс | 15.1–15.3 |
| all | 10.5–11.2 (~90 fps) | 11.4–11.6 (~87 fps) |

* **Фары ночью:** до 200 доп. проходов/кадр при 3–4 машинах; CPU-таймер видит 4.8–8.5 мс, кадр растёт на ~12 мс —
  остальное драйвер и GPU (каждый проход перерисовывает целый кусок трассы с MSAA 4x, хотя освещён только конус 72 м).
* **Кузова:** 70 % пути — стадия `atmo_body_shade` (1.3–3.6 мс): на каждую вершину каждого кадра заново строится
  `body_lighting()` (копия всей структуры Lighting) и полная `scene_color` (sqrt, 3×lround, tone, rim).
  Стоящие машины (старт) пересчитываются так же, как едущие. gate+owner+geometry ≈ 0.4–0.9 мс.

### План исправлений (по порядку выгоды)
1. **Фары одним проходом:** раз в кадр рисовать пятна всех машин в одну «карту света» сверху (текстура вокруг камеры),
   затем на каждый освещённый кусок трассы — один проход вместо N машин × 2 и только в зоне карты. Цель: −8…10 мс ночью.
2. **Кузова без изменения вида:** константы освещения — один раз на вызов, быстрый цикл по вершинам, кэш результата
   по (отрисовка, матрица, ревизия вершин, поколение освещения) — стоящие машины бесплатно. Цель: shade ×3–5 быстрее.
   (Альтернатива — аппаратное освещение D3D: shade ≈ 0, но tone/rim станут приближёнными — только с согласия владельца.)
3. UploadRing=1 по умолчанию (−0.45 мс, артефактов не было).
4. Для обычной игры `MRRRenderer.ini` `Trace = 0`.
