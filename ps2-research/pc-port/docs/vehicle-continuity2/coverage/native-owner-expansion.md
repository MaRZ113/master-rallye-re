## Shared engine contract versus per-family certificate

Exact-build original0054c9d0 was independently byte-verified: instance+8c identifies compiled model; instance+90 private list takes precedence over model+18; sentinel+4 root, sibling+8 and virtual+30 dispatch use current render instance. Existing caller-specific queue owner uses saved manager/queue-index record and verifies packet+74 backreference. This is reusable read-only engine machinery.

`renderer/race_model_native.hpp::race_context` defaults to27 roots and currently uses local27-node storage, exact termination/membership and emitted leaf dispatch checks. `atomic_race_certificate` scans27 and accepts only X-Trail13source profiles/healthy-damage certificates. Those constants are family-specific. `race_selected_list` and `race_descriptors` supply shared consumer logic, but simply changing roots or matching tag2 is not a valid family certificate.

Per family still prove current compiled source association, selected hierarchy/leaf membership, full source geometry plus ordered UV/winding, current generations/revisions, distinct conditional materials, crew/interior suppression, independent wheel owners/WORLDs and native deformation/restart/Reset lifetime. No count or source tag replaces these checks.
