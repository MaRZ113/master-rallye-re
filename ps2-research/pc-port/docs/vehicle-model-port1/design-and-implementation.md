# Vehicle model port1 implementation boundary

The working implementation partitions nine exact compiled CAR records across six PC
families. It does not replace a whole car, COMPLETE, wheel, physics body or damage
node. It preserves the accepted ReflectionMode4 as fallback/default. Enable
`RaceModelMode=1` separately. Only original PS2 `carshiny` surfaces proved by
the source join receive the existing Mode4 texture/additive transaction.

## Race material admission

`generate_vehicle_partitions.py` validates each original compiled face multiset,
its exact geometry digest and unique owner across the protected78DX corpus. The
generated registry contains hashes, multiplicities and a shiny/Stock policy. There
are no historical native buffer IDs, pointers, draw ordinals or texture-only rules.

Before native submission, the staged hook requires the supported executable,
current mirror coverage, device/reset identity, VB/IB generation/revision, complete
exact unsigned face multiset, original normal FVF, current race owner certificate,
native/effective state equality, exact native environment stage and Stock baseline
coordinate policy. Material-only identity is backed by the original source registry
and the existing submission-context predicate. A counts/layout prefilter alone
cannot admit anything. Unknown conditions preserve the original wrapper path.

The64-entry FIFO stores only source partition plans, keyed by15 current buffer,
layout, offset and lifecycle fields. Race/native-state admission is checked on every
draw before cache use. Reset generation, resource recreation or upload revision
changes require evaluation of current mirrored data. No old pointer is an authority.

Source-order runs are derived from the CURRENT index order. Complete multiset and
multiplicity validation happens first. All original faces, winding and native
attributes are retained. Every original index is submitted once, using contiguous
subranges of the same IB, with unchanged type/min-index/vertex-count/base-vertex.
There is no draw replay, delayed submission, new visual mesh or overlapping pass.

Original-order subdraw counts: LandCruiser8=33, LandCruiser9=7, Bruno4=5,
SeatBuggy7=9, ChevyBlazer7=3, Xtrail1=2, Forester8=5, Forester9=2,
Forester2=1. Runtime reordering may change run counts without changing the source
face identity. These are API subranges, not counts of objects or extra surfaces.
In particular the LandCruiser experiment increases native call overhead; runtime
FPS remains to be measured. The option defaults off.

## Native transaction and failures

The existing Mode4 source is captured/preflighted before suppressing any original
submission; driver/MSAA failure preserves the existing path. Every shiny subrange
uses the existing retained texture/COLOROP `ps2integration::Scope`. It changes only
stage1 texture and COLOROP=ADD, and restores both native/effective states immediately.
Flat, glass, unknown and untagged runs invoke the native draw with original states.

All identities and run metadata are allocated before any native submission. A
partial failure cannot fall back to rendering the whole original draw. The first
failed subdraw/pre-draw repair HRESULT is returned; otherwise the last native success
HRESULT is preserved. This is explicitly multi-subdraw semantics, not the original
single-DIP contract. An unsafe restoration remains pending for the existing next-API
repair and Reset lifecycle; failures are logged and reflection is disabled. Logical
game state is never overwritten. No new COM/texture owner is introduced by the
partition plan; original texture references and Mode4 target lifetime stay in the
existing transaction/capture owners.

The new hook is after `repair_reflection`, before the older reflection/foliage scopes.
It rejoins trace completion and grass/water world-draw observers. Unhandled draws
follow the earlier path. The frozen source remains unchanged; only0001 staged
patch changes CMake and the draw wrapper.0002 generator seam is unchanged and verified
twice for each staged variant. Single canonical build/staging roots are retained.

## Frontend

`FrontendGeometryDiagnostics=1` requests mirrors at startup independently of F10.
It performs at most128 coarse-filtered source evaluations and logs at most17 exact
Forester COMPLETE signatures per device. It reads native W/V/P and resource
generations, makes no Broker reads and does not mutate/suppress draws. Logs explicitly
say `model_owner_join_verified=false` and `replacement_enabled=false`. It is a
source-upload observation, not a frontend owner admission certificate.

The original PC mover selects `Vehicles/<family>/complete`, but desired selection
does not prove the loaded cache. The exact remaining join is current CarModel Egg
AI/en3d name+0xc, cached owner+0x74, current COMPLETE mesh submission and mirrored
VB/IB. F10frames1235/2726 prove layout/rotation but do not include source bytes.
Do not substitute their draw ordinals or buffer IDs for that join.

## Private model representation

`prepare_vehicle_models.py` reuses PackFS and the proved strict COMPLETE adapter.
All29 originals were converted into ignored `.assets/vehicles/*.ps2vehicle` with
original52-byte LE vertices, normals, packed colors, four source UV fields, XYZ/W,
control bits, strips/flags, literal material strings, ordered slots, hierarchy and
original GXI resources. No textures are unresolved. There is no winding guess or
trianglelist conversion. The versioned format has bounded sizes, finite-value/range
checks, source hashes, deterministic serialization and exact-EOF validation.

These are private prepared source assets, not implemented frontend replacement or
proven render-ready materials. All authored/conditional branches remain labelled;
their total is not a simultaneous polygon budget. Tag101 auxiliary collision data
remains opaque and unported; tag102 cylinder metadata is not used for rendering.
PS2 FORESTER remains a distinct future additional-car candidate.
