# Editable vehicle scene architecture

Changed: `editable-vehicle-project/1` is an external JSON journal referencing an exact immutable UVS scene and manifest. Source Fidelity returns the original representation; it rejects edit operations. MR Classic and User Customized evaluate independent derived arrays. No flag disables UVS, native buffer, binary writer or controller validation.

Stable IDs bind objects and faces. Operations move/add/delete vertices, change normals/UVs, add/delete faces, split/merge sections, duplicate an explicitly selected instance, add components, transform/hide nodes, assign/reset materials, and assign/remove exact-face Glow. A duplicate/new mesh is user-created. Split faces keep their identity; new/duplicated faces acquire deterministic journal IDs. Deleting a face removes its effect assignment instead of transferring an ordinal to its neighbour. Removing a used vertex requires deleting its faces first. A transaction rolls back on invalid final state. Source binary streams, damage targets and original material semantics remain in the parent, never rebound to changed arrays.

The journal has512 operations and32MiB JSON limits. Evaluated UVS/native allocation limits remain unchanged. Save is atomic and source-disjoint; unrelated files cannot be overwritten. Undo/Redo are journal cursor changes; Restore moves to the original cursor without destroying redo history. Evaluations cache by journal content and return defensive copies. Native compilation fully re-verifies the immutable parent, independently of preview caches.

Build route: evaluated UVS → existing universal_scene_bridge → SceneParts → scene_dx_writer/native_states. No donor-specific compiler. The derived hash pins the evaluated state, not an obsolete original triangle count. Native materials require explicit assignments; unassigned source shaders still block. Source effects replaced by an authoring choice are listed in the fixture manifest, with their original parent provenance retained.

Remaining: transactions with more than512 operations need a future checkpoint/compaction migration; whole-empty scenes cannot compile; skeletal/animated authoring and arbitrary native controller creation are unsupported. Existing native Workshop projects are not silently converted to the journal. The native-family compatibility snapshot is a static migration reference, not recovery of original GT semantics. Runtime installation is a later step.
