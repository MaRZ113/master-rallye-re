# Public tool documentation style

Every public tool or release page starts with the tool name and a one-sentence
description, followed by `## Quick Start` as its first operational section.

Use this order when the sections apply:

1. `## Quick Start`
2. `## What it does`
3. `## Requirements`
4. `## Compatibility`
5. `## Known limitations`
6. `## Troubleshooting`
7. `## Technical details`
8. `## Checksums`

Keep Quick Start to 3–7 direct steps that name the actual files, buttons, or
commands. It should answer what to download, what to run, and how to complete
the shortest successful workflow. Keep architecture and research history below
the operational guidance.
