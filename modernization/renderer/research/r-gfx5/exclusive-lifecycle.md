Thus the observed failure is a follow-up ownership/commit chain, not an initial native CreateDevice failure. No inference relies solely on Error2010. Old logs provide requested and accepted descriptors, plus native HRESULT breadcrumbs; separate pre/post native parameter snapshots were not available. New diagnostics explicitly add both. Existing Stock, Windowed and Borderless startup/reset samples are preserved in the same curated evidence file; they are historical observations, not runs of this DLL.

Configured Width/Height now own the Exclusive target. Zero selects the initial game dimension, or adapter dimension when the initial field is zero; the first successful native selection pins that target for the device. Subsequent transient HWND sizes cannot overwrite it. Auto mode therefore keeps the initial game resolution until restart/reconfiguration; choose explicit supported Width/Height for a modern exclusive resolution. This differs from Borderless's native-monitor auto policy. Windowed retains its separate pinned NORMAL versus actual maximized CLIENT ownership unchanged.

Each Exclusive Create/Reset enumerates adapter modes for target dimensions, requested/backbuffer or adapter format, and explicit refresh when supplied; CheckDeviceType uses FALSE, and enabled automatic depth is validated with CheckDeviceFormat/CheckDepthStencilMatch even when AA is Stock. Native Windowed is alwaysFALSE and interval is D3DPRESENT_INTERVAL_DEFAULT. Explicit refresh must match enumeration. Refresh0 remains0: it is the pinned D3D8 default constant and the old captured successful stock fullscreen path used it; actual driver refresh still needs observation. No invented refresh value is used.

Unsupported mode or depth pairing returns **D3DERR_NOTAVAILABLE before native Create/Reset**, with a specific validation reason. The last accepted descriptor survives failed Reset. There is no alias to Borderless and no Stock/Windowed retry for an Exclusive display failure. A native HRESULT is preserved after bounded attempts. MSAA negotiation remains8→4→2within the requested maximum, checks both color/depth with the actual fullscreenFALSE Windowed argument, and may retry once with the original AA/swap/count/flags. That retry retains the same Exclusive target/format/refresh/WindowedFALSE. Unsupported AA alone leaves Exclusive intact; Windowed/Borderless's existing bounded fallback policy remains.

Successful Exclusive creation/reset performs only a read-only window snapshot. The game and D3D8 own HWND style, placement, focus and activation. No proxy SetWindowLong, SetMenu, SetWindowPos, normal-window centering, maximize placement, or restore_window commit runs in this mode. Original game window behavior may still generate Reset requests; they now resolve to the chosen display mode without a proxy placement echo. Existing normal Windowed commit-echo handling is unchanged.

TestCooperativeLevel forwards its exact native result with transition-only diagnostics, bounded64records/device. Reset has no internal DEVICELOST/DEVICENOTRESET retry loop; the game's existing polling/recovery owns retry timing. The pool-aware registry retains MANAGED/SYSTEMMEM/SCRATCH generations on successful Reset, invalidates DEFAULT/unknown resources, clears temporal vehicle identities and UI epochs, and preserves generation-safe vehicle asset semantics according to the existing R-GFX4 policy. Failed Reset keeps pending native UI restoration and accepted display state. Native resource and COM identity suites remain mandatory regressions.

`display_native_attempt` is bounded128records/device and records sequence, operation, requested mode, effective mode, game descriptor, pre-native descriptor, returned descriptor, native HRESULT, AA request and reason. Validation-rejected operations are named explicitly and do not represent a native call. Compact quality metadata adds `exclusive_target` and `window_commit_status=exclusive_native_owned`; existing reset_policy indicates actual native calls. Successful Exclusive records must never show WindowedTRUE or a Stock/Borderless mode alias. No unbounded continuous draw logging was added.
